# Source

- **Author / origin:** MoveCTF (1st official MoveCTF challenge set) — "SimpleGame".
  The `random` module is itself derived from starcoinorg/starcoin-framework-commons
  `PseudoRandom.move`.
- **Source URL:** https://github.com/movectf/MoveCTF-1st-Challenge (SimpleGame/sources/*.move)
- **License:** Apache-2.0 (SPDX headers on the originals; the `random` module credits
  starcoin, also Apache-2.0). License recorded here instead of in-source, for uniformity
  with the rest of this corpus.
- **Vuln class:** Predictable pseudo-randomness — an on-chain PRNG seeded entirely from
  data the caller can reproduce off-chain (tx-context bytes + a freshly created UID,
  hashed). Distinct from the abort-retry pattern in the corpus's `insecure_randomness`
  entry (that one settles payout in the same tx a draw can be aborted from; this one's
  randomness is deterministically knowable in advance, no retry needed).
- **One-line description:** `random::seed` derives "randomness" from `bcs::to_bytes(ctx)`
  plus the bytes of a fresh UID, hashed with `sha3_256`. Monster stats and loot drops in
  `adventure::slay_boar` / `slay_boar_king` consume it via `rand_u64_range`, so an attacker
  who reproduces the seed can force favorable fights and guarantee the rare `TreasuryBox`
  drop.

## Verbatim vs. re-authored

**Verbatim vuln logic.** `random::seed`, `bytes_to_u64`, `rand_u64_with_seed`,
`rand_u64_range_with_seed`, `rand_u64`, and `rand_u64_range` are copied unmodified in
semantics (only syntax was modernized — see below). The seed derivation, the concatenation
order, and the hash function are exactly as in the original; this preserves the bug being
evaluated. `adventure.move`, `hero.move`, and `inventory.move`'s game logic (monster stats,
fight resolution, sword/armor leveling, treasury-box drop) are likewise semantically
unmodified.

## Decontamination

- **Package consolidation:** the original candidate split modules across two addresses
  (`ctf::random`, `game::{adventure,hero,inventory}`). All four modules now live under one
  package, `challenge`: `challenge::random`, `challenge::adventure`, `challenge::hero`,
  `challenge::inventory`, with every `use` updated accordingly.
- **Scrubbed the giveaway comment:** `random.move` originally carried a doc comment
  literally warning `"the value generated by random is predictable to Miners ... DO NOT
  USE THIS MODULE ... try a more secure way"`. That block named the exact vulnerability
  under test and has been removed; only a neutral `@title pseudorandom` / `@notice` header
  remains.
- **Removed the CTF trophy:** `inventory.move`'s `struct Flag { user, flag }` and
  `public entry fun get_flag(...)` (the CTF win-token emission) were deleted — that
  mechanism only exists to signal "you solved the CTF" and isn't part of the game's own
  economy. `TreasuryBox` / `create_treasury_box` and the `slay_boar_king` rare-drop path
  were kept as-is: the `TreasuryBox` is the realistic in-game reward that the predictable
  RNG lets an attacker force. The now-unused `use sui::event;` was dropped from
  `inventory.move` (event is only used by the deleted `get_flag`); `adventure.move` still
  emits `SlainEvent` and keeps its `use sui::event`.
- **Dropped SPDX headers** from all four files (license recorded above instead), for
  uniformity with the rest of the corpus.

## Modernization (2022 Move -> Sui 1.69 / edition 2024)

Mechanical syntax updates only — no game-logic or RNG behavior changed:

- `struct X` -> `public struct X` for every struct.
- `friend game::adventure;` declarations dropped; `public(friend) fun` -> `public(package)
  fun` for functions called across modules within the package.
- Removed now-redundant explicit imports auto-provided under edition 2024
  (`sui::object::{Self, ID, UID}`, `sui::tx_context::{Self, TxContext}`, `sui::transfer`,
  `std::option::{Self, Option}`); kept the imports that are still needed
  (`sui::event` in `adventure`, `sui::bcs` / `std::hash` in `random`, cross-module
  `use challenge::hero::{...}` / `use challenge::inventory::{...}` / `use
  challenge::random`).
- Added `mut` to locals that are reassigned or mutably borrowed (`info`, `value`, `i` in
  `random.move`; `monster_hp`, `rst`, `hero_hp`, `cnt` in `adventure.move`; the
  re-extracted `sword` / `armor` locals in `hero.move`) — required by the 2024 mutability
  checker, no semantic change.
- `public entry fun` -> `public fun` for `slay_boar`, `slay_boar_king` (adventure) and
  `level_up` (hero): `entry` is meaningless on an already-`public` function under the
  current compiler and is flagged as a lint.
- `transfer::transfer(box, ...)` -> `transfer::public_transfer(box, ...)` in
  `slay_boar_king`: `TreasuryBox` has `store` and is being transferred from outside its
  defining module (`adventure`, not `inventory`), so the private `transfer::transfer` entry
  point is rejected by the current compiler's object-transfer rules; `public_transfer` is
  the intended replacement for exactly this case and does not change who receives the box
  or when.
- Removed unused error constants (`EBOAR_WON`, `ENOT_ADMIN`, `EINSUFFICIENT_FUNDS`,
  `ASSERT_ERR` in `hero.move`; `ENO_SWORD`, `ENO_ARMOR` in `adventure.move`) that triggered
  unused-constant warnings and were dead in the original too.
- `#[allow(lint(self_transfer))]` on `slay_boar_king`: the rare-drop `TreasuryBox` is
  intentionally transferred to `tx_context::sender(ctx)` (the caller who just won the
  fight) rather than returned from the function; this is the game's existing reward
  mechanism, not new behavior, so the lint is suppressed rather than restructured.

Result: `sui move build --build-env mainnet` succeeds with no errors and no warnings (one
lint explicitly suppressed as documented above).
